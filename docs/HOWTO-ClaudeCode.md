# Памятка: работа над проектом с Claude Code CLI (Windows / PowerShell)

Держать открытым во время работы. Здесь только практика: что установить, как начать,
как вести каждую фазу и что делать, когда что-то идёт не так.

---

## 1. Что установить (один раз)

| Что | Как проверить, что стоит | Где взять |
|---|---|---|
| **.NET 10 SDK** | `dotnet --list-sdks` → должна быть строка `10.x` | dotnet.microsoft.com |
| **Git for Windows** | `git --version` | git-scm.com |
| **Docker Desktop** | `docker --version`, значок в трее | docker.com |
| **Claude Code CLI** | `claude --version` | см. ниже |
| **GitHub CLI** *(желательно)* | `gh --version` | cli.github.com |
| Visual Studio 2022 или VS Code | — | для чтения кода и отладки |

**Установка Claude Code в PowerShell:**
```powershell
irm https://claude.ai/install.ps1 | iex
```
Права администратора не нужны. **После установки закройте и заново откройте PowerShell** —
иначе `claude` не найдётся: изменения PATH не подхватываются в уже открытом окне.

Git for Windows формально не обязателен (без него Claude Code использует PowerShell как оболочку),
но для этого проекта git нужен в любом случае, так что ставьте.

**GitHub CLI** ставить не обязательно, но с ним Claude Code сможет сам создавать Pull Request
командой `gh pr create`. Без него PR придётся создавать вручную на сайте GitHub.
После установки один раз выполните `gh auth login`.

---

## 2. Про GitHub: что нужно, а что нет

**Отдельно «подключать» CLI к репозиторию не нужно.** Claude Code — обычная консольная программа:
вы запускаете её в папке проекта, и она работает с файлами на диске. Про GitHub она узнаёт из вашего
локального git: если папка связана с удалённым репозиторием (`git remote -v` что-то показывает),
то `git push` из-под Claude Code уйдёт туда же, куда ушёл бы у вас.

**Запушить сразу, до начала работы — да, обязательно.** Причины:
1. По заданию требуется история регулярных коммитов — она должна быть видна на GitHub.
2. Спецификация и `CLAUDE.md` окажутся в репозитории, а значит будут частью истории проекта.
3. Резервная копия: если что-то сломается локально, работа не пропадёт.

## 3. Подготовка репозитория (один раз)

**Шаг 1.** Создайте на GitHub пустой приватный репозиторий, например `zelda-arena`
(без README, без .gitignore — они появятся позже).

**Шаг 2.** В PowerShell:
```powershell
cd C:\Projects            # или другая папка для проектов
git clone https://github.com/ВАШ-ЛОГИН/zelda-arena.git
cd zelda-arena
```

**Шаг 3.** Разложите подготовленные файлы:
```
zelda-arena/
├── CLAUDE.md
├── .claude/
│   └── settings.json
└── docs/
    ├── SPEC.md
    └── design/
        ├── README.md
        ├── pages/      (home.html, tournament.html, ..., 404.html, login.html)
        └── assets/     (css, js, fonts, img — одна общая копия)
```

**Шаг 4.** Первый коммит:
```powershell
git add .
git commit -m "docs: project specification, design template and Claude Code config"
git push
```

**Шаг 5.** Заведите доску задач: на GitHub в репозитории вкладка **Projects → New project → Board**.
Создайте по задаче на каждую из 11 фаз. Это требование «использование таск-трекера» из задания.

## 4. Первый запуск

```powershell
cd C:\Projects\zelda-arena
claude
```

При первом запуске откроется браузер для входа в аккаунт — авторизуйтесь.
Claude Code автоматически прочитает `CLAUDE.md` из корня.

**Проверьте окружение** — введите в диалог:
```
Выполни dotnet --list-sdks, docker --version, git --version и покажи результат.
```
Если SDK 10.x нет или Docker не отвечает — сначала чините это, потом идите дальше.

**Первый настоящий промпт:**
```
Прочитай docs/SPEC.md полностью и CLAUDE.md.
Составь подробный план Фазы 0. Код не пиши до моего подтверждения.
```

Перед этим нажмите **Shift+Tab** — переключение режимов. Нужен режим **plan**: в нём Claude
исследует и предлагает план, но не меняет файлы. Индикатор режима виден внизу экрана.

## 5. Ритуал одной фазы

Повторяется 11 раз. Фаза = сессия = ветка = Pull Request.

**1. Новая ветка.**
```powershell
git checkout main
git pull
git checkout -b feature/phase-3-identity
```

**2. Новая сессия.** Если предыдущая ещё открыта — выйдите (`/exit`) и запустите `claude` заново,
либо введите `/clear`. Свежий контекст на каждую фазу — это важно: старая переписка мешает фокусу.

**3. Режим plan** (Shift+Tab) и промпт:
```
Прочитай docs/SPEC.md и docs/PROGRESS.md.
Мы начинаем Фазу 3 (Identity и безопасность). Составь план: список файлов,
которые появятся или изменятся, порядок работы, что проверим в конце.
Код не пиши.
```

**4. Прочитайте план.** Это самый важный момент — здесь дешевле всего что-то исправить.
Не понравилось — пишите словами, что не так, и просите переделать план.

**5. Запуск.** Shift+Tab обратно в обычный режим, дальше просто: `Приступай` или `Реализуй план`.

**6. Проверка.** В конце попросите:
```
Выполни dotnet build и dotnet test. Исправь ошибки, если есть.
```
Затем запустите приложение сами и посмотрите глазами:
```powershell
docker compose -f deploy/docker-compose.yml up -d
dotnet run --project src/ZeldaArena.Web
```

**7. Фиксация.**
```
Обнови docs/PROGRESS.md: что сделано в Фазе 3, что осталось, на чём остановились.
Сделай коммиты по Conventional Commits, разбив работу на логические части.
```
Потом:
```powershell
git push -u origin feature/phase-3-identity
```
И создайте Pull Request — через `gh pr create` (если поставили GitHub CLI, это может сделать
и сам Claude) или на сайте GitHub. Смержите в `main`, отметьте задачу на доске выполненной.

**8. Выход:** `/exit`.

## 6. Команды и горячие клавиши, которые реально нужны

| Что | Зачем |
|---|---|
| **Shift+Tab** | Переключение режимов: обычный → авто-принятие правок → **plan**. Основной инструмент |
| **Esc** | Прервать Claude на середине. Пошёл не туда — жмите сразу, не ждите |
| **↑** | История ваших предыдущих сообщений |
| `/model opus` / `/model sonnet` | Смена модели. Opus — планирование и архитектура, Sonnet — рутина |
| `/context` | Показать, чем занят контекст. Полезно, когда ответы стали хуже |
| `/compact` | Сжать историю, когда контекст переполняется |
| `/clear` | Очистить контекст полностью, начать с чистого листа в той же папке |
| `/resume` | Вернуться к одной из прошлых сессий |
| `claude --continue` | Продолжить последнюю сессию в этой папке |
| `/permissions` | Посмотреть и поправить права на выполнение команд |
| `/status` | Аккаунт, модель, версия, рабочая папка |
| `/config` | Настройки текущей сессии |
| `/help` | Полный список команд |

**Как вставить картинку** (скриншот ошибки, страница макета): перетащите файл в окно терминала
или скопируйте изображение и нажмите Ctrl+V.

## 7. Настройки

Уровней два:

* **Глобальные** — `C:\Users\ВЫ\.claude\settings.json`. Действуют во всех проектах.
* **Проектные** — `.claude/settings.json` в репозитории. У вас уже лежит готовый.

В проектном файле уже прописаны:
* `allow` — команды, которые выполняются без подтверждения (`dotnet build`, `dotnet test`,
  `git commit`, `docker compose` и т.д.). Без этого вы утонули бы в вопросах «разрешить?».
* `deny` — что читать и выполнять запрещено: секреты, минифицированные и вендорские файлы
  шаблона, `git push --force`, `rm -rf`.

Менять их обычно не нужно. Если по ходу работы Claude Code постоянно спрашивает разрешение
на одну и ту же безобидную команду — добавьте её в `allow` или разрешите через `/permissions`.

**Что НЕ делать:** не запускайте с флагом `--dangerously-skip-permissions`. Он отключает все
проверки; вне изолированного контейнера это опасно.

## 8. Приёмы, которые заметно улучшают результат

**Планировать раньше, чем кодить.** Каждая фаза начинается в режиме plan. Ошибка в плане стоит
одной реплики, ошибка в коде — часа переделок.

**Не описывать, как чинить баг.** Вставьте текст ошибки или стек-трейс и напишите `почини`.
Микроменеджмент («поменяй в файле X строку Y») работает хуже, чем постановка задачи.

**Требовать доказательств.** Перед мержем фазы:
```
Покажи git diff с main и объясни, где могли остаться дыры. Докажи, что требования Фазы 3 выполнены.
```

**Не бояться выбросить.** Получилось криво — не правьте по кусочкам:
```
Зная всё, что ты теперь знаешь, выброси эту реализацию и сделай заново, элегантно.
```

**Сверяться со спецификацией.** Раз в пару фаз:
```
Пройди по чек-листу docs/SPEC.md §19 и отметь, что уже выполнено, а что нет.
```

**Один экран за раз.** При вёрстке не просите сразу пять страниц. Даёте одну страницу макета —
получаете одну вьюху, проверяете в браузере, идёте дальше.

## 9. Что делать, когда идёт не так

| Симптом | Что делать |
|---|---|
| Ответы стали хуже, Claude «забыл» договорённости | `/context` → `/compact`, а лучше `/exit` и новая сессия с чтением `SPEC.md` и `PROGRESS.md` |
| Пошёл не в ту сторону | **Esc** немедленно, объясните словами, что не так, попросите переделать |
| Наделал лишнего, всё сломалось | `git checkout .` откатит незакоммиченное. Поэтому и нужны частые коммиты |
| `claude` не найден после установки | Закройте и откройте PowerShell заново |
| Постоянно спрашивает разрешения | Добавьте команду в `allow` в `.claude/settings.json` |
| Не собирается после его правок | Дайте вывод `dotnet build` целиком и напишите `почини` |
| Спорит или упирается в неверное решение | Сошлитесь на пункт спецификации: «см. docs/SPEC.md §7.3, доступ проверяется только через IEntitlementService» |
| Кончились лимиты | Переключитесь на `/model sonnet`, он экономнее |
