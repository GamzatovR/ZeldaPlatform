# Architecture Decision Records

Здесь фиксируются решения, которые дорого менять и о которых спросят на защите:
выбор архитектуры, лицензионно значимый выбор библиотек, модель разграничения доступа,
обращение с платёжными данными.

Записи не редактируются задним числом. Если решение пересмотрено — пишется новая запись
со статусом «Принято», а старая переводится в «Заменено ADR-XXXX».

## Индекс

| № | Решение | Статус | Фаза |
|---|---|---|---|
| [ADR-0001](ADR-0001-clean-architecture.md) | Clean Architecture из четырёх проектов, правило зависимостей проверяется тестами | Принято | 0 |
| [ADR-0002](ADR-0002-library-choices.md) | Shouldly, MediatR 12.x и Mapster — выбор по лицензии | Принято | 0 |
| [ADR-0003](ADR-0003-data-model.md) | Модель данных: ключи Guid v7, деньги объектом-значением, xmin как токен конкурентности, Identity в первой миграции | Принято | 1 |
| [ADR-0004](ADR-0004-application-skeleton.md) | Каркас Application: порт IQueryExecutor, порядок behaviors, рассылка доменных событий | Принято | 2 |
| [ADR-0006](ADR-0006-identity-behind-ports.md) | Identity за портами Application; готовый Identity.UI отвергнут | Принято | 3 |

Номер **ADR-0005 зарезервирован** за Фазой 4: `docs/SPEC.md` §7.4 требует зафиксировать
решение по роли `Premium` именно под этим номером, поэтому запись Фазы 3 получила 0006.

Запланированы: доступ по фичам вместо ролей и назначение роли Premium (ADR-0005, Фаза 4),
мнимая оплата и обращение с данными карты (Фаза 4), выбор хранилища новостей и EP-1 (Фаза 10).
