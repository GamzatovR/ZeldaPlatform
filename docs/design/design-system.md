# Дизайн-система ZeldaArena

Извлечена из макета в Фазе 5. Источник — `docs/design/assets/css/style.css` (авторский,
7772 строки) и разметка `docs/design/pages/*.html`.

> **Это основной источник для вёрстки.** К `pages/*.html` возвращаться точечно: открывать
> только файл того экрана, который верстается прямо сейчас (`CLAUDE.md`, «Работа с макетами»).
> Значения ниже перенесены в `src/ZeldaArena.Web/wwwroot/scss/_tokens.scss`; компоненты
> обязаны пользоваться только переменными оттуда.

## 1. Чего в макете нет

Разметка подключает 12 таблиц стилей, а в `assets/css/` лежит одна — `style.css`.
Это не ошибка чтения: файлов физически нет, и часть решений Фазы 5 продиктована именно этим.

| Чего нет | Что из этого следует |
|---|---|
| `responsive.css` | В `style.css` **ровно один** `@media`. Все брейкпоинты макета утеряны — адаптив пишем сами, mobile-first (раздел 8) |
| `bootstrap.min.css` | Разметка всех страниц на сетке Bootstrap 5. Подключаем Bootstrap из исходных SCSS, только нужные части |
| `boxicons.min.css`, `flaticon.css` | `boxicons.woff2` и `Flaticon.woff2` лежат в `assets/fonts/`, но без маппинга «класс → кодпоинт» бесполезны. Иконки заменены своим SVG-спрайтом (раздел 12) |
| `meanmenu.min.css` / `.js` | Мобильное меню шаблона. Пишем своё на ванильном JS |
| `dark-style.css` | Светлая тема шаблона. Проект остаётся тёмным — базовый `style.css` и есть тёмная тема |
| `owl.carousel`, `fancybox`, `magnific-popup`, `animate` | Слайдеры, лайтбоксы, анимации появления. По §16 (скорость загрузки) не переносим |
| 13 из 14 файлов `assets/js/` | Есть только `main.js`. Поведение переписывается на ES-модулях (§2: ванильный JS) |

**Дефект в самом `style.css`:** `.copyright-area p` ссылается на `var(--fontFamily1)`,
которой в `:root` нет (объявлены `--fontFamily`, `--fontFamily2`, `--fontFamily3`).
При переносе используем `--font-body`.

## 3. Контраст: первое сознательное отклонение от макета

§9.1 требует контраста не ниже 4.5:1, §16 — Lighthouse Accessibility ≥ 90.

`.default-btn`, `.add-to-cart-btn` и бейджи в макете — белый текст на `--mainColor`
`#fc0820`. Контраст **4.04:1** при размере 20px normal (это не «крупный текст» по WCAG:
нужны 24px normal или 18.66px bold). Требование не выполняется.

Решение — пара токенов вместо одного:

| Пара | Контраст | Где применяется |
|---|---|---|
| `--color-accent` `#fc0820` на `--color-bg` | **5.04:1** ✔ | Акцентный текст, ссылки, рамки, иконки |
| `#ffffff` на `--color-accent-strong` `#e00019` | **5.02:1** ✔ | Заливка кнопок и бейджей под белым текстом |
| `--color-text-muted` на `--color-bg` | 11.2:1 ✔ | Описания |
| `--color-text-dim` на `--color-bg` | 5.53:1 ✔ | Мета |
| `--color-text-dim` на `--color-surface-raised` | 4.70:1 ✔ | Мета внутри карточки |
| `#ffffff` на `--color-surface-raised` | 17.3:1 ✔ | Текст в формах и карточках |

Визуально `#e00019` от `#fc0820` почти неотличим, а требование выполняется.
Как фон блока (не под текстом) `--color-accent-strong` даёт 4.06:1 к фону страницы —
для нетекстовых элементов достаточно, порог 3:1.

## 4. Типографика

Три гарнитуры, каждая со своей ролью:

| Токен | Значение | Роль |
|---|---|---|
| `--font-body` | `"Teko", system-ui, sans-serif` | Интерфейс: меню, заголовки, кнопки, таблицы. Узкий конденсированный гротеск, вся типографика макета набрана им |
| `--font-display` | `"VerminVibes", "Teko", sans-serif` | Крупные декоративные заголовки: баннер, заголовок страницы |
| `--font-prose` | `"Poppins", system-ui, sans-serif` | Связный текст: абзацы, описания, значения полей формы |

- Teko и Poppins — Google Fonts (`@import` в макете, у нас `<link rel="preconnect">`
  плюс таблица стилей, `display=swap`, честный фолбэк в стеке).
- VerminVibes — локальный `@font-face`. В `assets/fonts/` есть только
  `Vermin-Vibes-V.ttf.woff`; объявленные в макете `.eot` и `.svg` отсутствуют,
  поэтому источник один, `format("woff")`.
- **Задел на Фазу 11:** перевести Teko и Poppins на самостоятельный хостинг,
  иначе `SecurityHeadersMiddleware` (§14.1) должен разрешать `fonts.googleapis.com`
  и `fonts.gstatic.com` в CSP.

## 7. Сетка

Bootstrap 5: `.container` (1210px), `.row`, `.col-{bp}-{n}`. Подключаются из исходных
SCSS только `reboot`, `grid`, `containers`, нужные утилиты, `forms`, `tables`,
`dropdown`, `collapse`, `modal`. Переменные Bootstrap переопределяются токенами
отсюда — переопределений каскадом и `!important` в проекте быть не должно.

`$container-max-widths` под макет: `xl: 1210px`, `xxl: 1210px`.

## 8. Брейкпоинты и адаптив

`responsive.css` в макете отсутствует, поэтому адаптив — наш, mobile-first,
по §9.1: **576 / 768 / 992 / 1200**. Проверка на 360, 768, 1440 px.

Правила, которые обязаны отработать при сужении:

| Что | Поведение |
|---|---|
| Шапка | До 992px горизонтальное меню сворачивается в кнопку-бургер и раскрывается панелью. `.container-fluid` теряет поля 100px |
| `h1` шапки страницы | 130px → 64px (768) → 40px (360). Иначе заголовок не помещается ни в один экран |
| Карточка матча | Три колонки 5/2/5 схлопываются в одну; логотипы команд с `position: absolute` переводятся в поток |
| Таблицы корзины и заказов | Оборачиваются в `.table-responsive` с горизонтальной прокруткой внутри блока — прокрутки у `body` быть не должно |
| Форма входа | Два столбца «Вход / Регистрация» → один; `padding: 40px 50px` → `25px 20px` |
| Секции | `--section-y` 100px → 70px до 768px, 50px до 576px |
| Анимация `glitch` у `h1` | Отключается под `prefers-reduced-motion` |

## 9. Кнопки

| Класс | Оформление |
|---|---|
| `.btn-primary` (макетная `.default-btn`) | Заливка `--color-accent-strong`, белый текст, `padding: 15px 40px 9px`, `font-size: 20px`, uppercase, без рамки и радиуса. При наведении фон заливается белым слева направо (псевдоэлемент), текст становится `--color-accent` |
| `.btn-outline` (макетная `.optional-btn`) | Прозрачный фон, рамка 1px белым, `padding: 15px 45px 9px`. Наведение — то же заполнение справа налево |

Асимметричный вертикальный `padding` (15px сверху, 9px снизу) — не опечатка макета,
а компенсация метрики Teko: у гарнитуры высокая базовая линия. Сохраняем.

**Фокус — второе сознательное отклонение.** В макете `:focus { outline: 0 !important }`,
что прямо нарушает §9.1. Заменяем на видимый `:focus-visible` с обводкой
`--color-accent` толщиной 2px и отступом 2px.

## 10. Формы

```
.form-control  высота 50px, фон --color-surface-raised, текст белый,
               радиус --radius-md, без рамки и тени, шрифт --font-prose 14px/500,
               padding: 2px 0 0 15px
```

- Внутри `.login-form` поля перекрашиваются в `--color-surface-sunken` (`#000000`) —
  утопленное поле на приподнятой карточке.
- Плейсхолдер белый, uppercase, `letter-spacing: 1px`, при фокусе становится прозрачным.
  **Плейсхолдер не заменяет `label`:** в макете подписи есть
  (`.login-form .form-group label`), оставляем их видимыми — иначе теряется доступность.
- `textarea.form-control` — высота авто, `padding-top: 15px`.
- Чекбокс кастомный: свой квадрат 19px, фон `#f5f5f5`, внутри квадрат 8px цветом
  `--color-accent`, рамка при наведении — акцентная.
- Группа полей: `margin-bottom: 25px`.

**Состояния валидации** в макете не описаны — вводим сами на токенах:
`.input-validation-error` получает рамку `--color-accent` 1px,
`.field-validation-error` — текст `--color-accent`, `--font-prose`, 14px.
Эти классы генерирует `jquery-validation-unobtrusive`, своих не изобретаем.

Карточка формы (`.login-form`, `.register-form`): фон `--color-surface-raised`,
`padding: 40px 50px`, `--radius-md`, `--shadow-card`. Заголовок `h2` — 40px/600 uppercase.

Шрифты иконок макета непригодны: `boxicons.min.css` и `flaticon.css` отсутствуют,
а без них `.woff2` не связать с именами классов. Вместо них — свой
`symbol`-спрайт `wwwroot/img/icons.svg` и tag helper:

```html
<icon name="search" />
```

## 13. Чего из макета не берём

| Элемент макета | Почему |
|---|---|
| `.zelda-cursor` / `.zelda-cursor2` | Подменённый курсор. Ломает доступность и не даёт ничего по критериям |
| `.jarallax`, `data-wow-*`, `animate__*` | Параллакс и анимации появления тянут два плагина ради декора (§16) |
| Слайдеры `.owl-carousel` | Единственное применение — витрина трейлеров и партнёров; заменяется сеткой |
| `.search-overlay` | Полноэкранный оверлей поиска. Поиск в проекте — обычная форма в шапке |
| `.sidebarModal` с лентой Instagram | Контента нет и не будет |
| Многоуровневые выпадающие меню шапки | В проекте 6 разделов, вложенность не нужна |
| Светлая тема (`dark-style.css`) | Файла нет; проект тёмный |

## 14. Порядок вёрстки

1. `_tokens.scss` — всё из разделов 2–6.
2. `base/` — `@font-face`, сброс, типографика.
3. `layout/` — сетка, шапка, подвал, шапка страницы, секция.
4. `components/` — кнопки, формы, карточки, таблицы, пагинация, бейджи, иконки.
5. `pages/` — только то, что не выражается компонентами.

**Правило без исключений:** за пределами `_tokens.scss` в SCSS не должно быть
ни одного шестнадцатеричного цвета и ни одного размера, которого нет в шкале.
Проверяется grep'ом в конце каждой фазы.
